## 14.01

> Определите, какое максимальное теоретическое и практическое количество потоков можно создать в x32 процессе с виртуальным адресным пространством размером 4 Гб. Учтите, что потоки имеют собственные стеки.

Поскольку все потоки будут делить общее вируальное адресное пространство, теоретический максимум для количества потоков можно оценить как $ M = (2^{32} - B)/\,{T}\,\, $, где $T\,\,$ - минимальные затраты памяти на один поток, а $B\,\,$ - размер данных, которые уже выделены для обслуживания процесса. В $T\,\,$ входит и стек, и другие данные, которые могут обслуживать поток в рассматриваемой системе (thread local глобалы например)

На практике количество доступных потоков скорее всего будет на порядки меньше. Есть и ограничения со стороны операционной системы, и ограничения по реальным ресурсам системы (оперативная память, время CPU).

С помощью следующего снипета я оценил практическое количество потоков на своей системе:

```C++
#include <vector>
#include <thread>
#include <chrono>
#include <iostream>

using namespace std::chrono_literals;

int main() {
    std::vector<std::thread> threads{};
    for (int i = 0;; ++i) {
        threads.emplace_back([](){  std::this_thread::sleep_for(20s); });
        std::cout << i << std::endl;
    }

    return 0;
}
```

Я получил следующие результаты:
```
...
31310
terminate called after throwing an instance of 'std::system_error'
  what():  Resource temporarily unavailable
```

При запуске данного снипета на [Godbolt](https://godbolt.org/) исключение вылетело уже на 13 потоке. Что вполне ожидаемо для облачного сервиса

## 14.02

> Сформулируйте аспекты, которые стоит учитывать при внедрении потоков для повышения производительности.

- Процент вычислений, который можно распараллелить
- Конкуренция за доступ к памяти
- Синхронизация
    - Какие примитивы и где использовать
    - Верификация?
- Гранулярность параллельных задач
    - Выгодно ли спавнить треды?
- Error handling
    - Исключения
    - Отмена задач (когда N потоков попытались выполнить последнюю задачу)
